# Markdown & Content Rules

- Use semantic HTML (headings h1-h6, lists, etc.) instead of presentational markup
- All case study content supports markdown-like syntax (## headings, - lists, **bold**)
- Maintain consistent heading hierarchy: h1 → page title, h2 → sections, h3 → subsections
- Never use inline styles — use Tailwind utility classes
- All text content should be editable from the CMS where possible
