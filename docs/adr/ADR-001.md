# ADR-001 — CMS Is the Portfolio Content Authority

- **Status:** Accepted (implemented)
- **Date:** 2026-08-18
- **Context:** The portfolio's early history contained hard-coded sample content in components. Production content now lives in the database (`Project`, `ProjectImage`, `CaseStudySection`, `SiteContent`, `Skill`, `Testimonial`, `ResumeExperience`, `Resume`, `SocialLink`). Public pages render from `lib/portfolio-content.ts`, which reads published records only. Development fixtures in `lib/dev-portfolio-fixtures.ts` are gated by `NODE_ENV === "development"`.
- **Decision:** Production portfolio content comes from the CMS/database. A new project must not require a new React page — it is created as data in the CMS.
- **Rationale:** Keeps the site content-editable without deploys, separates content from presentation, and makes projects additive via the admin UI.
- **Alternatives:** Hard-coding projects as React pages (rejected: requires deploys and code changes per project); external headless CMS (rejected: added platform dependency without benefit).
- **Consequences:** Content errors are data errors, not code errors; migrations are the only schema-level change vector; editors need the CMS.
- **Constraints:** Public reads must filter `published: true`; development fixtures must never render in production; no hard-coded production content.
