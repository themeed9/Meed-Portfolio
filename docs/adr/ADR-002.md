# ADR-002 — Database-Only Administrator Authentication

- **Status:** Accepted (implemented)
- **Date:** 2026-08-18
- **Context:** A historical `lib/auth.ts` allowed an environment `ADMIN_PASSWORD` as a runtime authentication fallback. That fallback was removed after a security audit (`docs/security-audit.md`, `docs/architecture-hardening-report.md`), and all exposed credentials were rotated. The current `lib/auth.ts` `authorize()` queries `prisma.user` by normalized email and verifies with `bcrypt.compare` against the stored hash.
- **Decision:** Admin authentication uses Prisma `User` + bcrypt + Auth.js. Environment `ADMIN_PASSWORD` must not be a runtime authentication fallback.
- **Rationale:** A database-only credential store keeps one source of truth, enables password rotation per user, avoids plaintext environment credentials, and removes a historical credential-exposure vector.
- **Alternatives:** Environment-variable password (rejected: exposed in history and non-rotatable per user); external identity provider (rejected: unnecessary operational overhead for a single-admin portfolio).
- **Consequences:** Admin login requires a seeded database `User`; maintenance tooling (`scripts/rotate-admin-password.ts`, seed) reads `ADMIN_EMAIL`/`ADMIN_PASSWORD` from the environment and updates the database explicitly.
- **Constraints:** Authentication failures fail closed; unknown emails compare against a dummy hash to keep timing uniform; login throttling remains active.
