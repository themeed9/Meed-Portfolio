# ADR-003 — Typed Case Study Block Architecture

- **Status:** Accepted (implemented)
- **Date:** 2026-08-18
- **Context:** Case studies were previously free-form rich text / hard-coded project pages. `lib/case-study.ts` now defines 19 typed section types (`project_tldr`, `problem_statement`, `product_principle`, `decision`, `evidence`, `before_after`, `annotated_screen`, `tradeoff`, `user_flow`, `interaction_states`, `architecture_diagram`, `design_system`, `ai_collaboration`, `timeline`, `outcome`, `reflection`, `next_steps`, `rich_text`, `gallery`), each with a Zod payload schema. `normalizeSection()` validates payloads and falls back to `rich_text` for unknown or legacy blocks. A single renderer (`components/projects/CaseStudyLayout` + `CaseStudySection`) renders every type.
- **Decision:** Case studies use typed, reusable sections rather than hard-coded project pages or one giant generic rich-text body.
- **Rationale:** Type safety per block, CMS-ordered blocks, safe fallback for legacy data, and no per-project code changes.
- **Alternatives:** Single rich-text document (rejected: no structure, validation, or componentization); per-project React pages (rejected: violates ADR-001).
- **Consequences:** Adding a section type requires a new type in `lib/case-study.ts` and a renderer branch; editors compose blocks in the CMS.
- **Constraints:** Unknown/legacy payloads must render safely; section content and payloads are bounded by Zod schemas.
