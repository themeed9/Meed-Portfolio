# ADR-008 — Database / Deployment Architecture

- **Status:** Accepted (implemented)
- **Date:** 2026-08-18
- **Context:** The repository once documented Neon as the PostgreSQL provider. The current runtime connects Prisma 7 via the `PrismaPg` adapter to **Supabase-hosted PostgreSQL**, and the application is deployed on **Vercel** with environment variables configured in the Vercel dashboard. Git history cleanup for previously committed environment files remains a separate, owner-controlled operation.
- **Decision:** Prisma connects to Supabase-hosted PostgreSQL. Vercel is the deployment platform. **This ADR supersedes any outdated Neon documentation.**
- **Rationale:** Current verified runtime reality; production build and deployment are exercised on Vercel; Supabase PostgreSQL is the active provider.
- **Alternatives:** Neon (rejected: superseded; not the current provider); self-managed PostgreSQL (rejected: operational overhead).
- **Consequences:** `DATABASE_URL` points at Supabase; no code path may assume Neon; migration tooling targets the configured provider.
- **Constraints:** No provider change without an owner-approved ADR; no secrets in the repository; environment variables are managed in Vercel.
