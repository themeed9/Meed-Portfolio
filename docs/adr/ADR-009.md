# ADR-009 — Motion Is Purposeful and Restrained

- **Status:** Accepted (implemented)
- **Date:** 2026-08-18
- **Context:** The `product-portfolio-motion` skill (`skills/product-portfolio-motion/SKILL.md`) and `lib/motion.ts` define a small, shared motion vocabulary (durations 120–500 ms, a fixed easing set, opacity/transform-first). The public portfolio treats motion as explanation, not decoration.
- **Decision:** Motion supports hierarchy, comprehension, and feedback. It must not become decorative UI bloat.
- **Rationale:** Editorial restraint and readability are core to the approved design system; motion that cannot state its purpose should be removed.
- **Alternatives:** Decorative/playful motion systems (rejected by the taste direction); per-component invented durations (rejected by the motion skill).
- **Consequences:** Motion uses shared tokens; reduced motion is a first-class mode; page content/navigation is never delayed by animation.
- **Constraints:** Any motion change must follow the motion skill's review routine and reduced-motion requirements.
