# Product Portfolio Taste

Treat `docs/portfolio-brand-system.md` as the repository’s visual contract. Read it before auditing or changing public UI. Preserve truthful content and product evidence; never improve appearance by inventing outcomes or artifacts.

## Design identity

Aim for senior, editorial, sophisticated, understated, intelligent, contemporary, visually quiet, product-focused, and intentionally premium. Communicate: **“Product designer who thinks carefully about systems.”**

Reject template-driven, generic SaaS, AI-futurist, cyberpunk, agency-like, playful, glass-heavy, startup-marketing, crowded, decorative, or Dribbble-first treatments. Let the work provide most visual interest.

Apply **simplicity through discipline**. Resolve decisions in this order:

1. Clarity
2. Hierarchy
3. Whitespace
4. Typography
5. Composition
6. Imagery
7. Restrained interaction

Do not solve weak hierarchy with decoration.

## Composition rules

- Use the shared responsive grid and spacing tokens. Do not invent page-specific maximum widths or arbitrary spacing.
- Pair narrow editorial copy with wider visual evidence. Keep long-form text within a controlled reading measure.
- Make headlines express decisions, tensions, insights, or outcomes rather than generic process labels.
- Use large type selectively and a small weight vocabulary.
- Maintain a neutral shell with one restrained accent. Allow project colours only inside controlled evidence areas.
- Prefer spatial grouping over cards. Use a container only when it communicates a relationship.
- Keep borders sparse, shadows rare, and radii small and systematic. Hierarchy must survive with shadows removed.
- Treat images as evidence: raw screens, annotations, states, flows, comparisons, system diagrams, and interaction clips. Avoid excessive device mockups.
- Pace case studies as statement → short explanation → evidence → annotation → decision → new tension.
- Keep the homepage product-first: positioning, selected work, thinking, product/technical capability, About, contact.

## Typography standard

Use the defined Display, H1, H2, H3, Body Large, Body, Small, and Micro roles. Check line length, wrap, widows, hierarchy, and baseline alignment. Prefer meaningful headings such as “The most important action couldn’t look secondary” over labels such as “Design.” Keep labels secondary and use Micro only for metadata.

## Micro-detail standard

Review baseline alignment, icon sizing, line length, optical spacing, label hierarchy, button height, hover treatment, image crop, border contrast, mobile padding, heading wrap, text widows, and focus states. Do not call a page complete while these remain inconsistent.

## Design QA routine

Run this review after completing any public page. Record failures and required changes; do not provide a vague pass.

### Visual system

- Is typography role-based and consistent?
- Is spacing tokenized?
- Does the page use the shared grid?
- Is colour disciplined?
- Are radius, borders, and shadows restrained?

### Hierarchy

- Can a recruiter understand the page within 10 seconds?
- Does the work dominate rather than decoration?
- Do headlines carry meaning while metadata stays secondary?

### Content

- Is important content buried?
- Are paragraphs within the editorial reading measure?
- Does every project image provide evidence?

### Motion

- Does each animation clarify hierarchy, causality, state, or spatial relationship?
- Can it be removed without losing meaning?
- Does reduced motion preserve immediate access to all information?

### Responsive

Review at 320, 375, 430, 768, 1024, 1280, and 1440+ pixels. Check overflow, safe padding, heading wraps, image crops, touch targets, diagrams, navigation, and reading order.

### Accessibility

Check keyboard access, visible focus, contrast, labels, semantic heading order, alternative text, touch targets, and reduced motion. Never claim compliance without formal testing.

### Polish

Check alignment, optical spacing, wrapping, crop quality, baseline rhythm, and mobile safe areas.

## Decision rule

When two solutions work, choose the one with fewer visual mechanisms, clearer hierarchy, better evidence visibility, and more consistent system behaviour. Use references only to study proportion, hierarchy, spacing, typography, interaction, composition, and restraint; never copy another site.
